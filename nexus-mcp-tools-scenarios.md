# MCP Nexus — тулы: описание и сценарии для агента

Краткий справочник: название тула, что делает, и когда агент его вызывает.
Сгруппировано по приоритету реализации.

---

## 🟢 P0 — ядро (MVP)

### `nexus_search_components`
**Описание:** generic-поиск компонентов (дистрибутивов) по всем или конкретному репозиторию;
работает для всех форматов (Maven, npm, Docker, PyPI, raw…).
**Сценарий:** пользователь спрашивает «есть ли у нас jackson-core в maven-releases?» или «найди все
пакеты со словом spring» — агент вызывает тул с `query`/`name`/`group` и отдаёт список с версиями.

### `nexus_search_assets`
**Описание:** поиск отдельных ассетов (файлов) с путями, размерами и контрольными суммами;
поддерживает поиск по SHA-1/256/512 и MD5.
**Сценарий:** «какой артефакт у файла с sha256 = abc123?» или «покажи все .jar в репозитории» —
агент передаёт контрольную сумму или формат и получает конкретные файлы с путями.

### `nexus_list_repositories`
**Описание:** список всех репозиториев с форматом, типом (hosted/proxy/group), URL и статусом online.
**Сценарий:** «какие у нас есть Docker-репозитории?» или «покажи все proxy» — агент фильтрует по
`format`/`type` и выводит обзор.

### `nexus_get_repository`
**Описание:** полная конфигурация одного репозитория (storage, blob store, proxy, cleanup, write policy).
**Сценарий:** «куда пишутся снапшоты в maven-snapshots и какая политика записи?» — агент берёт
детали перед тем, как что-то советовать или загружать.

### `nexus_list_components`
**Описание:** постранично перечислить все компоненты в конкретном репозитории.
**Сценарий:** «что лежит в internal-releases?» — агент проходит страницы по `continuation_token`
и собирает полный инвентарь.

### `nexus_get_component`
**Описание:** получение параметров дистрибутива по ID: группа, имя, версия, формат, список ассетов
с контрольными суммами.
**Сценарий:** после поиска пользователь просит «покажи детали этого компонента» — агент берёт `id`
из результатов поиска и раскрывает состав и checksums.

### `nexus_get_system_status`
**Описание:** здоровье инстанса — доступность, writable, версия, edition (OSS/Pro).
**Сценарий:** «Nexus живой? можно ли сейчас загружать?» или проверка edition перед вызовом
Pro-функций — агент дергает статус в начале сессии.

## 🟡 P1 — важные (следующая волна)

### `nexus_search_asset_download_url`
**Описание:** найти один ассет по критериям (включая SHA) и вернуть прямой URL для скачивания (302).
**Сценарий:** «дай прямую ссылку на последний core-utils.jar» или «ссылку на файл с этим sha1» —
агент сужает до одного ассета и отдаёт URL.

### `nexus_download_asset`
**Описание:** скачать содержимое ассета по content-URL в локальный файл (basic-auth, учитывает redirect).
**Сценарий:** «скачай мне этот артефакт в ./downloads» — агент передаёт `repository` + `path` и
сохраняет файл локально.

### `nexus_upload_component` *(write)*
**Описание:** загрузить компонент с ассетами в hosted-репозиторий; поля зависят от формата.
**Сценарий:** «залей версию 1.2.0 com.example:my-app в maven-releases» — доступно только во
write-режиме; агент собирает координаты и путь к файлу.

### `nexus_get_asset`
**Описание:** параметры одного ассета по ID: путь, checksum, размер, дата, blob.
**Сценарий:** «какой размер и sha512 у этого файла?» — агент раскрывает конкретный ассет из
результатов `search_assets`/`get_component`.

### `nexus_list_assets`
**Описание:** постранично перечислить ассеты репозитория.
**Сценарий:** «сколько файлов в raw-hosted и какие пути?» — агент проходит страницы и агрегирует.

### `nexus_get_maven_versions`
**Описание:** все версии Maven-артефакта, отсортированные, с пагинацией.
**Сценарий:** «какие версии spring-boot-starter у нас есть?» — агент отдаёт полный отсортированный
список без ручной фильтрации.

### `nexus_get_latest_version`
**Описание:** последняя (или последняя release/snapshot) версия артефакта/пакета.
**Сценарий:** «какая самая свежая версия lodash в npm-proxy?» — агент возвращает одну версию,
опционально с учётом prerelease.

### `nexus_list_docker_images` / `nexus_get_docker_tags`
**Описание:** список Docker-образов в репозитории / все теги конкретного образа.
**Сценарий:** «какие образы и теги есть в docker-hosted?» — агент сперва листит образы, потом
теги нужного.

### `nexus_get_npm_versions` / `nexus_get_pypi_versions`
**Описание:** все версии npm-пакета / PyPI-пакета с пагинацией.
**Сценарий:** «версии нашего внутреннего python-пакета?» — агент отдаёт список версий.

### `nexus_list_tasks`
**Описание:** список запланированных задач: id, тип, статус (WAITING/RUNNING), последний/следующий запуск.
**Сценарий:** «какие задачи обслуживания настроены и что сейчас выполняется?» — агент показывает
состояние cleanup/compact/repair.

### `nexus_get_task`
**Описание:** детали одной задачи по ID.
**Сценарий:** «когда последний раз отрабатывал cleanup и успешно ли?» — агент раскрывает задачу.

### `nexus_list_blob_stores`
**Описание:** список blob stores — имя, тип (File/S3), занято/доступно, число блобов.
**Сценарий:** «сколько места занято в хранилище?» — агент показывает загрузку по стораджам.

### `nexus_get_blob_store_quota_status`
**Описание:** статус квоты blob store (не превышен ли лимит).
**Сценарий:** «не упираемся ли мы в квоту по default-стору?» — агент проверяет и предупреждает.

### `nexus_get_read_only_state`
**Описание:** признак read-only режима (обслуживание).
**Сценарий:** проверка перед записью — «можно ли сейчас грузить артефакт?» — агент убеждается,
что система не в read-only.

### `nexus_get_usage_metrics`
**Описание:** метрики использования — число компонентов, суточные запросы, размер хранилища
(привилегия `nexus:metrics:read`).
**Сценарий:** «дай сводку по нагрузке и объёму за сутки» — агент собирает метрики для отчёта.
